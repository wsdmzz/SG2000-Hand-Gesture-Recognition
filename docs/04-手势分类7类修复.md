# 04 - 手势分类 7 类修复（#61-#72）

## 背景

实现自定义 7 类手势分类（fist, number1-5, thumbs-up）。核心阻碍：
1. TDL `OpenModel` 失败（Net setup failed）
2. 7 类模型加载后崩溃（Abort）或恒输出固定类

## 一、model_factory.json 解决 OpenModel 阻塞（#61）

### 症状
`TDL_OpenModel(h, TDL_MODEL_*, path, ...)` 报 `Net setup failed`。

### 根因
新版 tdl_sdk 的 `TDL_OpenModel` 需要 `model_factory.json` 的模型配置（input size / mean / std / rgb_order 等）。自定义模型必须在该 json 里声明。

### 解决
编辑评估板 `/mnt/data/model_factory.json`，为 CLS_HAND_GESTURE 等自定义模型添加：
```json
"CLS_HAND_GESTURE": {
  "types": ["fist","number1","number2","number3","number4","number5","thumbs-up"],
  "file_name": "gesture_7cls",
  "rgb_order": "rgb",
  "mean": [128,128,128],
  "std": [127.5,127.5,127.5]
}
```
此后 `TDL_OpenModel` 成功。

## 二、7 类模型崩溃根因（#66-69）

### 症状
7 类模型（sym INT8 / BF16）加载后崩溃（Abort），官方4类 asymmetric 正常。

### 源码级定位
1. cvimodel 输入 tensor `fmt` 决定 `TDLDataType`：
   - 7 类 sym/BF16 模型输入 `CVI_FMT_FP32` → `TDLDataType::FP32(8)`
   - 官方4类 asymmetric 模型输入 `CVI_FMT_INT8` → `TDLDataType::INT8`
2. `vpss_image.cpp` 的 `convertPixelFormat` 只接受 INT8(0)/UINT8(1)，对 FP32(8) 返回 `PIXEL_FORMAT_MAX` → `initFrameInfo failed` → **Abort**。

### 模型侧尝试（均失败）
- asym INT8 → 撞 TPU-MLIR v1.28.1 `AvgPool.cpp Assertion !asymmetric`（GAP 降成 AvgPool，无解）
- sym INT8 / BF16 / asym-qtable / quant_input → 输入恒 FP32
- **模型侧无法产出 INT8 输入的 7 类模型**，必须改库。

## 三、TDL 库修复（#71）

**方案（改库非改固件）**：修改 `tdl_sdk/src/framework/image/vpss_image.cpp` 的 `convertPixelFormat`，对 FP32/BF16 等非 INT8/UINT8 类型**不再返回 PIXEL_FORMAT_MAX**，保留已解析出的 YUV/RGB 图像格式（VPSS 输出数据本质仍是 8bit UINT8，模型声明 FP32 仅影响后续量化）。

**重编 libtdl_core.so**（手动增量重编，绕开 sample 子模块 CMake 失败）：
```bash
# compile_commands.json 重编 vpss_image.cpp.o + build.ninja 提取 107 个 .o + LINK_LIBRARIES 重链
bash /tmp/vpss_compile.sh
bash /tmp/tdl_link.sh
```
交叉工具链：`riscv64-unknown-linux-musl`（`-mcpu=c906fdv -march=rv64imafdcv0p7xthead`）。
新库 md5 `460df845`，覆盖评估板 `/mnt/system/lib/libtdl_core.so`。

**验证**：`tdl_cls7` 单图分类不崩（number5 0.77），`tdl_gesture_stream` 端到端实时推流稳定。

## 四、恒输出固定类问题（#72）

### 症状
7 类模型不崩了，但**恒输出固定类**（拿多张不同手势图都返回同一类）。

### 根因（决定性定位）
裸 cviruntime 直接加载同模型 + 0-255 fp32 输入 → **正确识别**；TDL 同模型恒输出固定类 → **问题在 TDL 预处理**：
- TDL `VpssPreprocessor` 对 FP32 输入模型**不做归一化**（0-255 直通），模型收到错误数据 → 恒单类。
- 且 `TDL_Classification` 对自定义 FP32 输入模型**不可用于实际识别**。

### 解决（双层修复）
1. **模型内置归一化**：`inject_normalize.py` 在 ONNX 输入后注入 `Sub(128)+Mul(1/127.5)`（即 `(x-128)/127.5`），模型自带归一化，TDL 只须直通 0-255。重校准 + 重转 `gesture_norm_sym.cvimodel`。
2. **裸 cviruntime 分类**（最终方案）：程序里手势分类改用裸 cviruntime `CVI_NN_Forward`（BGR ROI → 0-255 fp32 RGB NCHW → Forward → softmax），手检仍用 TDL。

### 结果
实时推流正确识别多变手势（number4 score=1.00 等）。

## 五、给复现者的话

1. **TDL_Classification 对自定义 FP32 输入模型不可用**——要么模型内置归一化走 int8，要么用裸 cviruntime。
2. **模型输入是 FP32 还是 INT8 由 cvimodel 的 fmt 决定**，asymmetric 才能出 INT8 输入，但撞 TPU-MLIR GAP bug。
3. **手动重编 libtdl_core.so** 是可行的（compile_commands + ninja 提取），不必重编整个固件。
