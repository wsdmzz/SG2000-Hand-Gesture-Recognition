# 03 - 摄像头取帧与推流（#50-#60）

## 背景

新固件（sophpi 编译）下，需要让 GC2083 摄像头实时取帧并推流。这一段解决了：
1. GC2083 传感器 init（默认回退 IMX327 的坑）
2. VI/VPSS 实时取帧
3. **VENC 内核 bug** 绕过（改用 OpenCV 软编码 JPEG）
4. MJPEG over HTTP 推流底座（断线重连稳定）

## 一、GC2083 取帧链路打通（#50-#53）

### 坑：sensor_cfg.ini 缺失
- 直接跑官方 sample_vio：回退到默认 **IMX327**（不是 GC2083），且触发内核 Oops。
- **根因**：`sensor_cfg.ini` 缺失/错误，VPSS 未正确识别 GC2083。

### 解决
1. 手工配置/重编支持 GC2083 的取帧程序。
2. 补全 `sensor_cfg.ini`（GC2083: bus 3, i2c 0x37, mipi 0）。
3. **决定性突破**：GC2083 实时取帧成功（6/6 帧抓取，1920×1080@30fps）。

## 二、VPSS 残留与取帧升级（#54-#55）

- **坑**：`vpss grp0 occupied`（上次程序异常退出残留）→ 需 `reboot` 或在程序里 `DestroyGrp` 关闭残留组。
- **突破**：`CVI_VPSS_DestroyGrp` 主动解 VPSS occupied + `CVI_SYS_Mmap` 将物理地址映射为可访问内存 → 真实落盘可看帧。

## 三、VENC 内核 bug 与软编码方案（#56-#58）

### 坑：cv181x_vpss 内核 Oops
- 用 VENC 硬编码 MJPEG/H.264 会触发 `cv181x_vpss` 内核 Oops（GP/MMU 问题）。

### 解决：OpenCV 软编码
- 用 **opencv-mobile（milkv 预编译）** 的 `cv::imencode(".jpg", ...)` 软编码 JPEG。
- **绕开 VENC 内核 bug**，MJPEG over HTTP 实时推流打通（里程碑 #58）。

## 四、推流底座稳定（#59-#60）

### 断线重连缺陷
- 连出流正常，但浏览器刷新/断线重连有卡点。

### 修复
- **独立 HTTP 线程**：`accept` + `recv` 断线检测 + `poll`/`select` 超时。
- `poll` 非阻塞 + 发送超时，客户端断开时正确关闭 fd 并继续 accept。
- 推流底座稳定版（#60）。

## 五、给复现者的话

1. **sensor_cfg.ini 必须正确**——否则回退默认 sensor 且可能内核 Oops。
2. **VENC 硬编码在 CV181X 上不可靠**（内核 Oops）→ 用 OpenCV 软编码。
3. **VPSS grp 残留**是取帧常见坑，程序要主动 DestroyGrp 或用前 reboot。
4. 推流必须用**独立线程 + 非阻塞 + 断线检测**，否则 HTTP 长连接会卡死主循环。
