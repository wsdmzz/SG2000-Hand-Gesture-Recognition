# 02 - 固件移植与 SD 卡启动（#31-#44）

## 背景

官方分类 API 在新/旧固件上都是死路，且旧固件的 tdl_sdk 版本过旧。为获得新版 TDL API（含可用的 `TDL_Classification`），需要**自行编译新固件并移植到评估板**。

评估板为 Milk-V Duo S（SG2000），原生 eMMC 启动。烧写 eMMC 有硬件协作风险，因此走 **SD 卡启动**路径。

## 一、sophpi 移植（#31-#35）

1. 确认评估板 = Milk-V Duo S（SG2000），选定 sophpi SDK（sophgo 官方开发板 SDK）。
2. 把 Duo S 板型复制到 sophpi，调整 defconfig 使其可识别。
3. 修复 u-boot dtsi 里 wifi_pin 无 label 导致的 dtc 报错（源头修复）。
4. 完整编译固件成功，**新版 TDL_* 分类库（`TDL_Classification`）编入固件**。

## 二、SD 启动卡制作（#36-#41）

### 路径选择
- eMMC 烧写需 USB 烧录 + 硬件配合，有风险 → 放弃。
- 改为 **SD 卡启动**（路径 B）。

### 制作要点（踩坑记录）
1. **boot.sd 格式**：CIMG → 必须是 **FIT**（`mkimage` 封装 kernel + fdt）。
2. **分区方案**：3 分区 `BOOT / MISC / ROOTFS`，rootfs 在 **p3**，匹配 `root=/dev/mmcblk0p3`。
3. **rootfs 写入**：必须真实写入完整 ext4 rootfs。**坑**：设备节点损坏导致 `dd` 只写了普通文件而非分区 → 用官方 `rootfs.sd` 完整镜像解决。

## 三、启动成功（#42 决定性里程碑）

新固件从 SD 卡完整启动成功，进入 Linux（`root@sg2000` shell）。

## 四、恢复 WiFi（#43-#44）

- SD rootfs 补齐 **AIC8800 WiFi firmware**（原固件自带路径丢失）。
- 评估板 WiFi 联网成功 + 新版 `TDL_Classification` API 确认部署。

## 五、给复现者的话

1. **SD 启动的 rootfs 必须写进分区节点**（不是普通文件），设备节点损坏是隐形坑。
2. **boot.sd 必须是 FIT 格式**（含 kernel+fdt），CIMG 旧格式无法引导。
3. 新固件移植的核心收益：**新版 tdl_sdk（有可用的 `TDL_Classification` / `TDL_Detection` C API）**。
4. 网络：新固件默认无 dropbear/sshd，需自行部署（见 docs/06）。串口 `/dev/ttyUSB0` 115200 可作调试通道。
