# 05 - 关键点手势识别（当前最佳方案）

## 背景

图像分类方案（docs/04）虽能识别手势，但实时 ROI 裁剪形态与训练图不一致导致"偏 fist"等问题。关键点方案用**手部 21 个关键点坐标**做手势分类，**不受 ROI 裁剪形态/光照/背景干扰**，是官方推荐的根治方案。

## 一、方案构成（官方 tdl_models）

```
YOLOV8N_DET_HAND  → 手部检测（已有）
KEYPOINT_HAND     → 21 个手部关键点（keypoint_hand_128_128_INT8）
CLS_KEYPOINT_HAND_GESTURE → 关键点手势分类（1x42 输入，9 类）
```

官方 9 类关键点手势：`0:fist,1:five,2:four,3:none,4:ok,5:one,6:three,7:three2,8:two`

模型来源：`https://github.com/sophgo/tdl_models/tree/main/cv181x`
- `keypoint_hand_128_128_INT8_cv181x.cvimodel`（1.2MB）
- `cls_keypoint_hand_gesture_1_42_INT8_cv181x.cvimodel`（40KB）

## 二、关键模型输入/输出（probe 确认）

```
keypoint_hand:          输入 [1,3,128,128] fmt=6(INT8) qscale=48.1
                        输出 [1,21,2,1] fmt=0(FP32)  （21 关键点 x,y 坐标）
cls_keypoint_hand_gesture:
                        输入 [1,42,1,1] fmt=6(INT8) qscale=142.2
                        输出 [1,9,1,1] fmt=0(FP32)   （9 类手势）
```

## 三、关键坑：TDL_Keypoint 输出恒定坐标

### 症状
用 `TDL_Keypoint(h, KEYPOINT_HAND, roi_img, &kpt)` 时，无论手部 ROI 怎么变，输出坐标恒定（如 kpt0=(0.539,0.484)）。

### 根因
`TDL_Keypoint` 走 **VPSS 硬件预处理**路径，对软件构造的 NV21 ROI 图未被正确处理 → 模型收到固定/错误输入 → 输出恒定。

### 解决：裸 cviruntime 关键点
裸 cviruntime 直接推理 `keypoint_hand` 模型（ImageNet 归一化 + INT8 量化），**关键点正确随手势变化**：
- 输入预处理：RGB + ImageNet 归一化 `(x-mean)/std`，`int8 = value * qscale`
- 实测标准手图：fist / number5 关键点明显不同（kpt0 从 0.578 到 -0.016 等）

### 量化与官方一致
```c
// keypoint_hand 输入: ImageNet 归一化
const float imean[3] = {123.675f, 116.28f, 103.53f};
const float istd[3]  = {58.395f, 57.12f, 57.375f};
// int8 = (x-mean)/std * qscale

// 关键点分类输入: qscale * 坐标（官方 HandKeypointClassification 一致）
float tf = qscale * kpt[i];   // clamp [-128,128], round
```

## 四、手框 NMS 合并（解决多框竞争）

### 症状
一手被检成分散多个框（手指框 + 手掌框），各自识别手势 → 结果不稳定/跳变。

### 解决
对检测框做简易 NMS：IoU > 0.25 的框**合并为包络框**（取并集，覆盖完整手）→ 只对合并后的单手框做手势识别。

## 五、当前识别能力（实测）

- ✅ **number1-5 稳定识别**（官方 one/two/three/four/five）
- ❌ fist 判不准（官方模型对握拳本身区分度差，标准 fist 图也判成 none）
- ❌ thumbs-up 恒 none（官方 9 类无此类）

**说明**：官方 `cls_keypoint_hand_gesture` 是 9 类，与自定义 7 类需求（fist/1-5/thumbs-up）不匹配。若需完整支持 fist/thumbs-up，需**重训练 7 类关键点分类器**（用 42 维关键点坐标训练小模型转 cvimodel），见 README 后续计划。

## 六、集成到推流

`code/streaming/tdl_gesture_kpt_stream.c`：
1. 手检（TDL）→ 手框 NMS 合并
2. 裁手部 ROI → 裸 cviruntime 关键点（ImageNet 归一化）
3. 42 坐标 → 裸 cviruntime 关键点分类 → 9 类手势
4. 绘制 21 个关键点（黄点）+ 手框（绿框）+ 手势标签（红字）
5. MJPEG over HTTP 推流

编译：`code/build/build_tdl_gesture_kpt_stream.sh`

## 七、给复现者的话

1. **关键点模型用裸 cviruntime 推理**（绕开 TDL_Keypoint 预处理 bug）。
2. **关键点输入需 ImageNet 归一化**（RN/BN 统计均值方差），不能直接喂 0-255。
3. **分类输入按 qscale 量化**（与官方 HandKeypointClassification 一致）。
4. **手框要 NMS 合并**，否则一手多框导致手势跳变。
5. 裸 cviruntime 验证工具：`code/keypoint/kpt_cls_e2e.c`（关键点→分类端到端）、`kpt_raw_test.c`。

## 相关验证

- 关键点模型裸推理：fist/number1/number5 关键点正确发散
- 端到端：手检→关键点→9 类分类链路跑通
- 实时推流：number1-5 稳定识别
