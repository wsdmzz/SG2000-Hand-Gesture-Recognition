# SG2000（Milk-V Duo Module 01）会话历史与实施报告

> 记录日期：2026-11-20
> 设备：Milk-V Duo Module 01（SG2000，eMMC，512MB）
> 摄像头：CAM-GC2083（MIPI，I2C1/总线3，0x37）
> 屏幕：Milk-V 8HD，800×1280 MIPI DSI
> 本文档为本次完整会话过程的实施记录与踩坑速查，供后续接手/复现使用。

---

## 一、项目目标

1. 在 Duo Module 01 上安装系统、配置网络。
2. 解决 USB 网络（CDC-NCM）不可用问题。
3. 设计并实现"三任务挂墙采集"设备：手势（手 21 点）、人脸/头部（眼/脸）、躯体（17 点），
   同一场景采集、分任务存储，供后续分发采集、汇总标注训练。
4. 在评估板实现采集器：摄像头预览 + 分任务分类存储 + 元数据 CSV。
5. 后续接 TPU（TDL）手势/关键点推理。

## 二、阶段历程（时间线）

### 阶段 1：系统安装（eMMC 烧录）
- 官网文档：https://milkv.io/zh/docs/duo/getting-started/duo-module-01
- 下载 CviBurn 烧录工具 + DuoS eMMC V1.1.2 固件。
- 用 `usb_dl.exe -s linux -c cv181x -i .\rom` 通过 USB 烧录 eMMC（需取下 SD 卡）。
- 成功标志：`USB download complete`；蓝灯闪烁正常启动。
- 结果：✅ 系统正常启动（Linux 5.10.4，riscv64）。

### 阶段 2：网络配置
- USB-NCM（CDC-NCM）默认 192.168.42.1，但 Windows 侧驱动报错（Problem 28 / 0xe0000228）。
- 排查：系统缺 usb80236.sys/rndismp6.sys；netrndis.inf 不匹配 `USB\MS_COMP_RNDIS`。
- 最终方案：设备端切 `usb.sh → usb-rndis.sh`，自写 `milkv_rndis.inf` + **自签名 catalog**，
  在 `testsigning` 模式下用 pnputil 安装 → USB 网卡成功，设备 IP 192.168.42.1，延迟 <1ms。
- 同时配置 WIFI：HUAWEI_E5576_674D（5GHz），固定 WIFI MAC 88:00:33:77:59:2A，IP 稳定 192.168.66.52。
- 结果：✅ 双通道（USB RNDIS + WIFI）联网，SSH 可用。
- 详见：`docs/USB_RNDIS网络修复记录.md`

### 阶段 3：采集方案文档修订
- 明确原则：**同场次采集、分任务标注与训练**（不是"一帧图三套标签"）。
- 采集合并（省人力、场景一致、脸锚点需手脸同帧）；标注/训练分开（分目录 + sessions.csv task 字段）。
- 详见：`docs/数据采集方案_挂墙三任务.md`

### 阶段 4：采集程序设计
- 设计文档：`docs/采集程序设计_屏幕版.md`
- 800×1280 竖屏布局设计（预览区 + 状态栏 + 选择区 + 操作区）。
- 分类存储结构：`/mnt/data/collect_YYYYmmdd_HHMM/P{n}/{task}/D{cm}/pos_xx/Lx/img_*.jpg` + `sessions.csv` + `manifest.json`。

### 阶段 5：采集程序源码（核心，已本地验证）
- 路径：`src/collector/`
  - `storage.c`：分类目录、JPEG 落盘、CSV、manifest、剩余空间检查
  - `state.c`：状态机（IDLE/READY/RECORDING/PAUSED）、2fps 节流、低空间保护
  - `config.c`：site_info.txt / board_id（两板区分）
  - `ui_model.c`：触摸命中分区
  - `main.c`：单实例锁、事件处理、采集主循环（含 COLLECTOR_AUTOREC 自动录制开关）
  - `platform_cvitek.c`：VI/VPSS/VO/VENC/GT911 平台适配层
  - `platform.h` / `include/collector.h`
- 本地 WSL gcc 编译 + 冒烟测试通过（目录/CSV/manifest/UI 命中正确）。

### 阶段 6：SDK 集成（构建/部署闭环）
- 环境：WSL Ubuntu-22.04（WSL2）+ gcc11 + make + host-tools（5.9G riscv64 交叉工具链）。
- SDK：`duo-buildroot-sdk`，最终切到 **tag Duo-V1.1.2（commit ed9cf2b4e）= 板子固件版本**。
- 编译：手动脚本 `scripts/compile_collector_manual.sh`（V1.1.2 头 + 库 + xthead ABI + `-DSENSOR_GCORE_GC2083`）。
- 部署：SSH 免密 + `cat local | ssh root@192.168.42.1 'cat > /mnt/system/collector'`（dropbear 无 sftp）。
- 结果：✅ RISC-V 静态 ELF 上板运行，创建 `collect_*/sessions.csv`。

### 阶段 7：ABI 错位（关键坑）
- 现象：`VI_StartSensor ret=0xffffffff`。
- 根因：**SDK develop 头文件与板子固件 ABI 不一致**（SAMPLE_VI_CONFIG_S 结构大小不同）。
- 解决：切到板子固件配套 **V1.1.2 tag + `-march=rv64imafdcv0p7xthead -mabi=lp64d` + `-DSENSOR_GCORE_GC2083`**。
- 结果：✅ VI/VPSS 初始化成功（GC2083 1080p@30）。

### 阶段 8：摄像头 ISP tuning（全黑根因）
- 现象：采集 JPEG 全黑 + 绿伪影。
- 诊断：`CreateIsp` 报 `sensorName(0) mismatch, mwSns:2083 != pqBinSns:2053`
  —— 板子 `/mnt/cfg/param/cvi_sdr_bin_GC2083` 实为 GC2053 的 tuning（错配）。
- 解决：**不加载错配 PQ bin**（用 ISP 默认 tuning），摄像头正常出图（415KB/帧，色彩正常）。
- 结果：✅ 摄像头成像正常。

### 阶段 9：采集存图（核心里程碑）
- VENC JPEG 在 V1.1.2 稳定（develop 才有内核 Oops）。
- get_jpeg：VPSS 取帧 → CVI_VENC(PT_JPEG) → GetStream 取码流。
- 结果：✅ 1080p JPEG（42KB/帧压缩后 415KB 有内容）、分类目录、sessions.csv 每帧一行、2fps。
- 注意：VPSS 输出尺寸必须 = VENC 尺寸（曾因 720 vs 1080 不匹配导致绿屏/黑屏）。

### 阶段 10：屏显示（VO）
- 8HD 面板原生 800×1280；VO 驱动只支持 720×1280 等（无 800×1280 模式，USER 自定义被拒）。
- 结果：屏显示 720×1280 + 右侧 80px 黑边（VO 硬限，不影响采集）。
- 踩坑：VO 全屏 + VPSS 贴顶 + RGN 一次性改动 → 黑屏/花屏；VPSS 旋转 + VO 绑定 → 花屏；
  VO 旋转 → 失败。最终回退到 VO 720×404 预览（正常）。

### 阶段 11：触摸交互（GT911）
- `insmod /mnt/system/ko/3rd/gt9xx.ko` → `/dev/input/event0`（goodix-ts）。
- 实现 platform_input_poll 读 ABS 坐标 + BTN_TOUCH 抬起 → ui_hit_test 分区。
- 底部 5 行选择（人员/任务/距离/位置/光照）+ 操作行（开始/完成/停止）。
- 状态：代码已实现并部署，**触摸坐标范围（GT911 raw vs 屏）尚未最终验证/校准**。

### 阶段 12：方向调整（进行中）
- 决策：改用 **算能官方完整 SDK（sophgo/sophpi）** 编 eMMC 固件（duo-buildroot-sdk 为裁剪示例）。
- 评估：`sophpi` 仓库默认分支 `sg200x-evb`（含 SG200X），板级/dev 配置参考
  `github.com/wsdmzz/SG2000-Hand-Gesture-Recognition`（同板同 GC2083，已跑通）。
- 待办：拉取 sophpi → 核对 SG200X/duos board + 8HD panel + GC2083 + 构建脚本 → 编 eMMC → 烧录。

## 四、踩坑速查表（重要）

| 坑 | 症状 | 解决 |
|---|---|---|
| CDC-NCM 驱动 Error | USB 网卡不可用 | 切 RNDIS + 自签名 catalog + testsigning |
| SDK ABI 错位 | `VI_StartSensor 0xffffffff` | 用固件配套 V1.1.2 tag + xthead + GC2083 宏 |
| ISP tuning 错配 | 全黑/绿伪影 | 不加载错配 PQ bin（用默认 tuning）|
| VPSS 残留 | `0xc0068004` | 启动前 `CVI_VPSS_StopGrp/DestroyGrp` |
| VPSS 尺寸不匹配 | 绿屏/黑 | VPSS 输出尺寸 = VENC 尺寸 |
| VENC Oops | develop 硬编码崩溃 | V1.1.2 稳定；或软编码 |
| VO 无 800×1280 | 80px 黑边 | VO 硬限，接受 720×1280+黑边 |
| VO 全屏+RGN 黑屏 | 黑屏 | 回退 VO 720×404 预览；OSD 需分步调 |
| VPSS/VO 旋转 | 花屏 | 旋转路径受阻，屏横放需重编 panel |
| dropbear 无 sftp | scp 不可用 | `cat local \| ssh 'cat > file'` |
| BUSY: Text file busy | 覆盖旧 collector 失败 | `killall collector` 后再部署 |
