# 采集程序（8 寸屏本地版）设计

> 日期：2026-11-19
> 适用：Milk-V Duo Module 01 (SG2000) + GC2083 + 8 寸 MIPI DSI 屏
> 目标：**去掉 HTTP 交互**，改为 8 寸屏本地 UI；分任务分类存储；供两套板子分发采集。
> 配套：`数据采集方案_挂墙三任务.md`（采集脚本与分布要求以其为准）

---

## 1. 改造目标（相对现有采集器）

| 项 | 现有 `collect_gesture.c` | 本设计 |
|---|---|---|
| 参数选择 | HTTP 网页点选 | **8 寸屏 UI**（触摸/按键） |
| 预览 | HTTP 推流 640×384 | **屏幕实时预览（缩略）**，存盘 1080p |
| 存储 | `/tmp/gesture_data` 混存 | `/mnt/data/collect_*/` **按任务/人员/距离/位置/光照分目录** |
| 元数据 | 无 | `sessions.csv`（每帧一行）+ `session_meta.json`（会话全局） |
| 交互 | 浏览器 | 触摸（I2C）或 GPIO 按键/编码器 |
| 运行态 | 多实例风险 | **单实例 + 启动自检 + 采集前建议重启** |

## 4. 交互与状态机

```
        ┌──────────┐  选好参数
        │  IDLE    │───────────►┌──────────┐
        └──────────┘            │  READY   │
             ▲                  └────┬─────┘
             │ 停止会话               │ 开始
             │                  ┌────▼─────┐  暂停   ┌──────────┐
             └──────────────────│ RECORDING│◄───────►│  PAUSED  │
                                └────┬─────┘         └──────────┘
                                     │ 本档完成
                                     ▼
                               写该档 manifest → 回 READY（连续下一档）
```

- **RECORDING**：每 500ms 抓一帧 1080p → JPEG q≥90 → 落盘 + 追加 CSV。
- **PAUSED**：不写盘，可切换下一档。
- **本档完成**：写该档 `manifest.json`（帧数、时长、参数），UI 提示。
- **停止会话**：关闭当前会话，`sync`，回到 IDLE。
- 安全保护：剩余空间 < 500MB 自动暂停并提示；同一档重复开始提示"已有数据"。

## 5. 存储结构与命名

```
/mnt/data/collect_YYYYmmdd_HHMM/
  site_info.txt                     # 安装高度/角度/FOV 标定/板号/日期
  session_meta.json                 # 会话全局：板号、操作员、屏参、开始/结束时间
  P1/
    hand/D10/pos_mid_high/L1/
        img_000001.jpg ...
        manifest.json               # 本档帧数/参数/起止时间
    face/D10/L1/
    eye/D05/L1/                     # 眼皮专项
    body/D20/L1/
  P2/ ...
  negative/                          # 空场景/干扰物
  sessions.csv                       # 全量索引（每帧一行）
```

**目录编码**：`D10 = 1.0m`、`pos_mid_high = 中×高`、`L1/L2/L3 = 光照档`、任务 `hand/face/eye/body`。

**sessions.csv 字段（每帧一行）**：

```
file,person,task,distance_m,pos_h,pos_v,light,frame_seq,timestamp_ms,board_id
P1/hand/D10/pos_mid_high/L1/img_000001.jpg,P1,hand,1.0,mid,high,L1,1,1732012345678,B01
```

- `file` 为相对 `/mnt/data/collect_*/` 的路径，便于汇总。
- 每档 `manifest.json` 冗余记录，防止 CSV 丢失后无法回溯。

## 6. 代码模块划分

| 模块 | 职责 | 依赖现有 SDK/API |
|---|---|---|
| `main.c` | 单实例锁、初始化顺序、主循环、启动自检 | SDK 基础 |
| `cam_capture.c` | VPSS 1080p 出图（VB 池按 1920×1080 NV21 重算，块数≥6）| 沿用 `vi_vpss_capture_test` |
| `jpeg_encode.c` | NV21→JPEG q≥90，线程/双缓冲避免阻塞采集 | cvitek VENC/JPEG 或 libjpeg |
| `storage.c` | 目录/命名、CSV 追加（缓冲+周期 flush）、manifest、剩余空间检查 | POSIX |
| `ui_screen.c` | 屏幕初始化 + 预览显示 + 控件绘制 + 触摸/按键事件 | 取决于显示方案（见 §7） |
| `input.c` | 触摸或 GPIO 按键/编码器 → 统一事件（UP/DOWN/OK/BACK）| evdev / gpio |
| `state.c` | 状态机 + 当前参数（person/dist/pos/light/task）| — |
| `config.c` | 读取 `site_info.txt`/`session_meta.json`、板号 | — |

**数据流**：`VPSS(1080p) → [每500ms] → JPEG → storage` ；`VPSS(缩略) → ui_screen 预览`。
采集与 UI 解耦：采集线程按定时器落盘，UI 线程按需刷新，互不阻塞。

## 7. 屏幕显示方案（三选一）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. `/dev/fb0` 直绘** | mmap framebuffer，自绘文本+矩形（可加 FreeType） | 简单、依赖少 | 控件需自绘；需确认 fb 存在 |
| **B. cvitek VO + MIPI DSI panel** | 走 SDK VO 层输出到 DSI panel（dts 配屏参） | 性能好、帧率高、官方链路 | 需屏参 dts、改 SDK 显示配置 |
| **C. LVGL on fb/DRM** | 移植 LVGL，控件丰富 | UI 好看、开发快 | 引入 LVGL 依赖，占内存 |

**倾向**：若 SDK 已有 `fb0` 或 VO 输出样例 → **B（VO+DSI）** 最稳；
纯 UI 文本+缩略图且无触摸库 → **A** 最快落地。C 仅在需要复杂控件时选。

## 8. 操作员采集流程（屏上）

1. 开机 → 采集器自检（摄像头/屏/存储）→ 显示 UI。
2. 先填 `site_info.txt`（安装完成一次性，可由开发侧预置）。
3. 每位被采者：选人员代号 → 按 `数据采集方案` §5 选任务/距离/位置/光照 → 喊口令 → 按"开始"。
4. 每档结束按"本档完成"，UI 显示该档帧数；继续下一档。
5. 全部完成按"停止会话"，屏幕提示"可安全取下/汇总"。
6. `sync` 后导出数据（见 §9）。

## 9. 两套板子数据汇总

- 两板程序相同，仅 `board_id` 不同（B01/B02），写入 `session_meta.json`。
- 每次采集生成独立 `collect_YYYYmmdd_HHMM/`，互不覆盖。
- 汇总：把两板的 `collect_*` 目录拷到同一台机器，
  合并 `sessions.csv`（加 `board_id` 列已有），按 §7.2 **按人划分** train/val/test。
- 汇总脚本（PC 端 Python）后续单独提供：校验帧完整性、按分布统计、
  抽取 INT8 校准集（每模型 200–500 帧）。
