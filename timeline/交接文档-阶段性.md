## 四B、7类模型部署崩溃 ===已解决===（验证#71，2026-08-12）

### 结论
7类手势模型（sym INT8 / BF16）在 TDL 实时识别+推流全链路**已修复并稳定运行**。
- **根因**：cviruntime 模型输入 tensor `fmt` 决定 `TDLDataType`；7类模型输入 `CVI_FMT_FP32` → `TDLDataType::FP32(8)`；`vpss_image.cpp` `convertPixelFormat` 只接受 INT8(0)/UINT8(1)，对 FP32(8) 返回 `PIXEL_FORMAT_MAX` → `initFrameInfo failed` → Abort。官方4类 asymmetric 输入 `CVI_FMT_INT8` 故稳定。sym/BF16/asym-qtable/quant_input 转换均无法产出 INT8 输入模型（asym 撞 TPU-MLIR v1.28.1 AvgPool assert，sym 恒 FP32 输入）。
- **修复（B1 方案落地，改库非改固件）**：修改 `tdl_sdk/src/framework/image/vpss_image.cpp` `convertPixelFormat`，对 FP32/BF16 等非 INT8/UINT8 类型**不再返回 PIXEL_FORMAT_MAX**，保留已解析出的 YUV/RGB 图像格式（VPSS 输出数据本质仍是 8bit UINT8，模型声明 FP32 仅影响后续量化，不影响图像帧内存格式）。手动增量重编 `libtdl_core.so`（compile_commands.json 重编 vpss_image.o + build.ninja 提取 107 个 .o + LINK_LIBRARIES 重链，绕开 sample 子模块 CMake 失败）。
- **部署**：新库 md5 `460df845` 覆盖评估板 `/mnt/system/lib/libtdl_core.so`。
- **验证**：
  1. `tdl_cls7` 单图分类 INT8：`number5 score=0.77`/`number4 score=0.98`，EXIT=0
  2. `tdl_cls7` BF16：`number5 score=0.87`，EXIT=0
  3. `tdl_gesture_stream` 端到端实时推流（之前必崩路径）：GC2083 init OK → 手检+7类BF16加载 OK → VI→VPSS OK → MJPEG :8881 推流 → **稳定 180+ 帧无崩溃**；开发机 curl :8881 拉到 17.8MB 流（http 200）
- **验证#72 续（识别正确性）**：
  - 发现：即使不崩，TDL 对 FP32 输入模型**恒输出固定类**（换手势不变）。裸 cviruntime 直接加载同模型 + 0-255 fp32 输入则**正确识别**（t5→number5 等）→ 根因是 TDL `VpssPreprocessor` 对 FP32 输入模型不做归一化
  - **修复**：(a) 模型内置归一化 `inject_normalize.py` 在 ONNX 注入 (x-128)/127.5 节点，重校准+重转 `gesture_norm_sym.cvimodel`（md5 2661c0）；(b) `tdl_gesture_stream.c` 手势分类改用**裸 cviruntime**（手检仍用 TDL，`cls_norm_infer` 做 BGR ROI→0-255 fp32 RGB→CVI_NN_Forward）
  - **结果**：实时推流正确识别多变手势（number4 score=1.00 / number2 等），`curl :8881` 抓 7-10MB MJPEG 流正常
  - **教训**：TDL_Classification 对自定义 FP32 输入模型不可用于实际识别，须用裸 cviruntime 或模型内置归一化+进 TDL int8 输入
