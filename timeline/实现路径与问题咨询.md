## 一、项目最终目标（我想做成的样子）

在 SG2000 评估板上，用摄像头实时：
1. **框出手的位置**（手检测）
2. **识别 7 类手势**（fist / number1 / number2 / number3 / number4 / number5 / thumbs-up）
3. 画面叠加框 + 手势标签，RTSP 推流到 Fedora 观看

关键要求：**用自己的模型**（因为 sophgo 官方预训练手势模型对我手势识别率不够，实测泛化差）。

## 三、遇到的问题与解决过程（含坑）🔧

### 3.1 摄像头/系统层
1. **V1.1.4 固件无法枚举 GC2083** → 换 V2.0.1 固件解决
2. **"删分区重建"扩展脚本导致 kernel panic**（`mmcblk0p3` 找不到）→ 改 growpart 安全扩展
3. **VPSS Grp0 残留**（`0xc0068004`）→ 重启评估板解决
4. **camera-test.sh PATH 缺 ai/ 子目录** → 脚本写完整路径

### 3.2 模型转换层（核心攻坚）
1. **Keras3 导出 ONNX 是 NHWC**，常量折叠误判通道 `C:160 vs kernel:3` → 后端 `--address-assign` 越界崩溃
   → **解决**：改 PyTorch 训练（天然 NCHW）
2. **ReduceMean opset18 axes 是输入张量**，TPU-MLIR 不认 → `fix_onnx_reducemean.py` 改属性
3. **Conv 缺 kernel_shape 属性**（ONNX 允许省略但 TPU-MLIR 必须显式）→ 修复脚本补齐
4. **当初以为工具链版本问题**（milkv fork 崩溃）→ 实测 sophgo v1.28.1 + 官方 blazeface 成功，证明**是模型结构问题不是工具链问题**

### 3.3 评估板部署层（⚠️ 当前卡点）
1. **自编译 `sample_vi_hand` 摄像头初始化失败**（`Failed to get senor information`）→ 因 duo-tdl-examples 自带库与固件运行库版本不一致（libsys.so 哈希不同）
2. **sophgo `yolov8n_det_hand` 手检测模型对真实手图 0 检测**（8张全 0）→ 疑似预处理/模型兼容，未深入
3. **sophgo `cls_hand_gesture` 手势分类对真实手势全判 none** → 泛化差，选择不用，改用自己的
4. **`cvi_sample_classifier` 工具错判**：7 张图全偏（非fused偏num4 / fused RGB偏num2 / fused BGR偏num5），宿主机全对
5. **API 手写路径层层阻塞**（详见下）

## 四、当前阻塞：自定义 cvimodel 在评估板上的部署 ⛔

这是**最后一道未攻克的壁垒**。我已确认：

### 4.1 已验证的事实
| 通道 | OpenModel | 推理 | 结果 |
|------|-----------|------|------|
| `RAW_IMAGE_CLASSIFICATION` | ❌ 0xc0010102 | - | 模型打开失败 |
| `IMAGE_CLASSIFICATION` | ✅ | ❌ 0xc001010b | 推理报 `NOT_YET_INITIALIZED` |
| `cvi_sample_classifier` 工具 (fused) | ✅ | ✅（但错判）| 能推理，结果错误 |

### 4.2 已尝试的初始化组合（仍推理失败）
- `CreateHandle`（无 VPSS）→ 010b
- `CreateHandle2(&tdl, 1, 0)` 分配 VPSS 组 → 010b
- `CVI_TDL_SetSkipVpssPreprocess(true)` → 010b
- `CVI_TDL_SetPreParam(factor=0.0078431, mean=1.0, format=RGB_PLANAR)` → 010b
- RGB vs BGR_PLANAR fused 编译 → 结果都错判

### 4.3 关键矛盾
**宿主机 PyTorch 100% 正确，评估板无论工具还是 API 都错/无法初始化**。这强烈暗示评估板侧存在**系统性的输入/预处理/初始化差异**，尚未识别。

## 五、最终路径存在的缺口（要解决的）🎯

### 完整链路图
```
[1]训练 ✅ → [2]转cvimodel ✅ → [3]评估板加载推理 ⛔ → [4]实时摄像头流水线 ❌ → [5]画框手势标注+推流 ❌
```

### 具体缺口清单

**缺口 A（关键）：自定义分类模型如何在评估板正确推理**
- 现象：`IMAGE_CLASSIFICATION` 推理报 `NOT_YET_INITIALIZED`；`RAW` 通道打不开模型；工具错判
- 需要：确定正确的 `CVI_TDL_*Classification` 调用 + VPSS/VB池初始化 + 预处理参数对齐
- **可能的解法方向**：
  1. 反推 `cvi_sample_classifier` 工具（fused能手跑）的完整初始化序列，复刻到自写程序
  2. 确认 `SetPreParam` 用法（可能需要先 `CVI_TDL_GetPreParam` 拿默认再改）
  3. 显式 `CVI_TDL_SetVBPool(tdl, 0, 2)`（参考检测示例）
  4. 可能需要 `CVI_TDL_SetVpssThread` / ROI 设置

**缺口 B：工具错判的根因（输入像素差异）**
- 现象：宿主机正确，评估板工具错判（RGB偏/2、BGR偏5）
- 需要：定位是预处理缩放、通道顺序、还是归一化差异
- 方向：用 `cvi_sample_classifier` 工具 + 逐像素对比；或确认 fused 模型 `--fuse_preprocess` 的实际 scale/mean 应用方式

**缺口 C：手检测（画框）环节**
- 现象：sophgo `yolov8n_det_hand` 对真实手图 0 检测
- 需要：确认是模型不兼容还是预处理，或是否需要自己的手检测模型（工作量大）
- 若目标改为"不画框，只分类整幅画面"，可跳过此缺口（但语义损失）

**缺口 D：实时摄像头 + 分类 + 推流一体化程序**
- 合成缺口：把摄像头帧 → ROI/整幅 → 分类 → 叠加标签 → RTSP
- 依赖：A、B 解决后，基于 `sample_vi_fd` 的 VPSS/VENC/RTSP 框架改造成分类版
- 固件库已有 `CVI_TDL_Isp_Image_Classification`（直接吃 ISP 数据）可能是实时通路，待研

## 六、我的技术建议（按优先级）

### 优先解决缺口 A（评估板推理），因为它卡住后面所有
最可能突破口（按成功率排序）：
1. **复刻 `cvi_sample_classifier` 工具的完整初始化**（它已证明能推理我们模型）——通过符号/行为反推，加 `SetVBPool`、`SetVpssDepth` 等
2. **改用 `CVI_TDL_Isp_Image_Classification`**（固件实时分类专用，接 ISP 数据，可能绕开 RAW/普通分类的初始化门槛）
3. **官方咨询 V2 固件 `CVI_TDL_*Classification` 正确调用方式**（现有问题文档已备好）

### 关于手检测（画框）的现实选项
- **选项 1（保留画框）**：需解决 sophgo 手检测模型的 0 检测问题，或自训手检测（工作量大）
- **选项 2（放弃严格画框）**：只对整幅画面做手势分类，输出手势标签不画框——可先用缺口 B 打通，快速出可用 demo
- 推荐先走选项 2 验证"自定义模型能实时识别"，再考虑画框增强
