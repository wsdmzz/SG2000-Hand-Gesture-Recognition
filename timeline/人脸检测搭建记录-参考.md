## 二、核心结论（先看这个）

1. **固件必须选对**：本项目最终用 **V2.0.1 固件**（`duo-buildroot-sdk-v2`）解决摄像头问题。
   - V1.1.4 老固件在 J8 接口上无法枚举 GC2083，切 V2 后正常。
2. **分区扩展用 `growpart`**，不要用"删分区重建"脚本（会导致分区错乱、kernel panic）。
3. **排线方向 / J8 接口 / 传感器配置** 是摄像头能否 init 的关键物理项。

## 三、SD 卡烧录（Fedora 宿主机）

### 1. 下载固件镜像
在 [duo-buildroot-sdk-v2 releases](https://github.com/milkv-duo/duo-buildroot-sdk-v2/releases) 下载：
```
milkv-duos-musl-riscv64-sd_v2.0.1.img.zip
```
解压得到 `.img`（本项目路径 `/home/oooa/Milk-V-Duo/ai/`）。

### 2. 确认 SD 卡设备号（务必二次确认，避免写错盘）
```bash
lsblk            # 读卡器一般显示为 /dev/sdc
```

### 3. 完整烧录（覆盖整卡）
```bash
sudo dd if=/home/oooa/Milk-V-Duo/ai/milkv-duos-musl-riscv64-sd_v2.0.1.img of=/dev/sdc bs=4M status=progress conv=fsync
sync
```

### 4. 确认分区表是"三分区"
```bash
sudo fdisk -l /dev/sdc
```
预期：
```
/dev/sdc1 * 1 262144  128M  c  FAT32 (BOOT)
/dev/sdc2  262145 266240  2M  0  Empty (保留)
/dev/sdc3  266241 1839104  768M 83 Linux (ROOTFS)
```
> ⚠️ DuoS/Duo Module 01 的 rootfs 是**分区3**（中间有保留分区），不是分区2。

## 四、扩展 rootfs（growpart 安全方案）

> ❌ **踩坑教训**：最初用"`parted rm 3` + 重建"脚本，因起始扇区不对齐等原因导致分区表错乱，sdc3 丢失，插回评估板 kernel panic（`VFS: Cannot open root device "mmcblk0p3"`）。
> ✅ **正确做法**：用 `growpart` —— 它只把分区终点往后移，**不删分区、不重建**，绝不破坏分区结构。

```bash
# 1. 卸载相关分区
sudo umount /dev/sdc1 2>/dev/null; sudo umount /dev/sdc3 2>/dev/null

# 2. 用 growpart 安全扩展分区3到磁盘末尾（Fedora 需先安装）
sudo dnf install -y cloud-utils-growpart
sudo growpart /dev/sdc 3     # 输出 CHANGED: partition=3 ...

# 3. 刷新分区表
sudo partprobe /dev/sdc

# 4. 检查并扩展 ext4 文件系统
sudo e2fsck -f /dev/sdc3
sudo resize2fs /dev/sdc3

# 5. 验证：分区3应变为 ~7.4G
sudo fdisk -l /dev/sdc
```

**完成后把 SD 卡插回评估板并上电。**

## 五、系统连接评估板

### 1. 连接方式
- **USB-NCM 网络**（评估板通过 USB 线连 Fedora）：评估板侧 `192.168.42.1`，Fedora 侧自动分配 `192.168.42.x`
- **串口调试**：`/dev/ttyUSB0`（CP210x），波特率 115200

### 2. SSH 登录（登录凭据可能在串口上确认/重置）
```bash
ssh-keygen -R 192.168.42.1 2>/dev/null   # 首次换固件后清除旧主机密钥
sshpass -p milkv ssh root@192.168.42.1
```

### 3. 登录凭据（本项目实测）
- 默认 `root/milkv`
- 若 SSH 登不上：**用串口登录**进 root shell，
  ```bash
  echo -e "milkv\nmilkv" | passwd root   # 重置密码
  ```

## 六、配置 WiFi（可选，用于局域网观看）

> 评估板通过 WiFi 入局域网后，可以在 Fedora（同一局域网）直接拉流，比 USB-NCM 稳。

### 1. 写入 WiFi 配置
```bash
cat > /etc/wpa_supplicant.conf << 'EOF'
ctrl_interface=/var/run/wpa_supplicant
ap_scan=1
update_config=1

network={
	ssid="你的SSID"
	psk="你的密码"
	key_mgmt=WPA-PSK
}
EOF
```

### 2. 启动连接
```bash
ip link set wlan0 up
wpa_supplicant -B -i wlan0 -c /etc/wpa_supplicant.conf -D nl80211
sleep 5
wpa_cli -i wlan0 status    # 应看到 ssid=..., wpa_state=COMPLETED
dhcpcd wlan0               # 获取 IP
ip addr show wlan0         # 拿到 WiFi IP，如 192.168.8.128
```

### 3. 路由器绑定固定 IP（可选）
在路由器 DHCP 服务器按 **MAC 地址绑定**评估板的 wlan0：
```
MAC : 88:00:33:77:41:f1
固定 IP : 192.168.8.124
```
绑定后评估板每次拿到固定 IP `192.168.8.124`，方便拉流。

### 4. 开机自启 WiFi
```bash
cat > /etc/init.d/S80wifi << 'EOF'
#!/bin/sh
sleep 5
ip link set wlan0 up 2>/dev/null
wpa_supplicant -B -i wlan0 -c /etc/wpa_supplicant.conf -D nl80211 2>/dev/null
dhcpcd wlan0 2>/dev/null
EOF
chmod +x /etc/init.d/S80wifi
```

## 七、运行人脸检测 + RTSP 推流

### 1. 确认关键文件存在
```bash
ls /mnt/system/usr/bin/ai/sample_vi_fd          # 人脸检测+推流程序
ls /mnt/cvimodel/scrfd_768_432_int8_1x.cvimodel # 人脸模型（SG2000 用 768x432）
ls /mnt/system/usr/bin/camera-test.sh           # 官方测试脚本
```

### 2. 官方测试脚本修复
`camera-test.sh` 默认 `sample_vi_fd` 不在 PATH 里（报 `not found`），需改完整路径：
```bash
cat > /mnt/system/usr/bin/camera-test.sh << 'EOF'
#!/bin/sh
export LD_LIBRARY_PATH=/mnt/system/lib:/mnt/system/usr/lib:/mnt/system/usr/lib/3rd
/mnt/system/usr/bin/ai/sample_vi_fd /mnt/cvimodel/scrfd_768_432_int8_1x.cvimodel
EOF
chmod +x /mnt/system/usr/bin/camera-test.sh
```

### 3. 持续后台推流
```bash
export LD_LIBRARY_PATH=/mnt/system/lib:/mnt/system/usr/lib:/mnt/system/usr/lib/3rd
nohup /mnt/system/usr/bin/ai/sample_vi_fd /mnt/cvimodel/scrfd_768_432_int8_1x.cvimodel > /tmp/stream.log 2>&1 &
# 成功后评估板终端打印：rtsp://<评估板IP>/h264
```

### 4. 查看推流日志确认
```bash
tail /tmp/stream.log
# 应看到：
# ViPipe:0,===GC2083 1080P 30fps 10bit LINE Init OK!===
# Initialize RTSP
# rtsp://192.168.8.128/h264
```

> ⚠️ 若报 `CVI_VPSS_CreateGrp(grp:0) failed 0xc0068004`（VPSS 组已存在），是**内核媒体资源残留**，**重启评估板**即可解决（进程退出但内核 VPSS 组未释放）。

## 八、在 Fedora 观看实时视频

评估板正在通过 RTSP 推流，在 **Fedora 终端**执行：

### 推荐：ffplay
```bash
ffplay -rtsp_transport tcp rtsp://192.168.8.128/h264
```
降低延迟版：
```bash
ffplay -rtsp_transport tcp -fflags nobuffer -flags low_delay rtsp://192.168.8.128/h264
```

### mpv 也可
```bash
mpv --rtsp-transport=tcp rtsp://192.168.8.128/h264
```

> - `192.168.8.128` 换成评估板实际 IP（`192.168.8.128` / 路由器绑定后的固定 IP，或 USB-NCM 的 `192.168.42.1`）
> - 先 `ping <IP>` 确认网络通

### 显示效果
- GC2083 实时画面（1280x720 H264）
- 画面实时框出**检测到的人脸**
- 评估板终端同时打印 `face count: N`

## 九、关键排错速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| `VFS: Cannot open root device "mmcblk0p3"` kernel panic | SD 卡分区表被"删分区重建"脚本搞乱 | 重烧镜像，用 `growpart` 扩展 |
| 摄像头探测不到 GC2083 | 排线方向/接触、接口、固件 | 核对 J8 排线方向，换 V2 固件 |
| `camera-test.sh: sample_vi_fd: not found` | 程序在 `ai/` 子目录，不在 PATH | 脚本写完整路径 |
| `CVI_VPSS_CreateGrp(0xc0068004)` | 内核 VPSS 组残留 | **重启评估板** |
| SSH `Permission denied` | V2 默认密码不确定 | 串口进 root，`passwd root` 重置 |
| 重启后 WiFi 断 | V2 无 WiFi 自启 | 加 `/etc/init.d/S80wifi` 脚本 |
