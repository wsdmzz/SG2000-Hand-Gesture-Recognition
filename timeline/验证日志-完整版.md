## 验证 #3：PDF 文档《TDLSDKSoftwareDevelopmentGuide_zh.pdf》关键发现
- **时间**：2026-08-04
- **目标**：从官方 SDK 指南查找正确部署方式
- **关键发现**（文档硬证据）：
  1. **`SkipVpssPreprocess` 文档说明**（839行）：
     > TDL SDK 默认使用**内部 VPSS** 进行预处理(skip=false)；skip=true 时模型输入必须外部预处理，
     > 通常用于 VI 直接 binding VPSS 且单一模型场景。
     → **推测：我设置 skip=true 反而破坏了内部 VPSS 初始化，导致 NOT_YET_INITIALIZED**
  2. **官方手势识别 API**（4.2.6章节，输出为 `cvtdl_object_t*` 含 name）：
     - `CVI_TDL_Hand_Detection(handle, frame, cvtdl_object_t *meta)`（手框）
     - `CVI_TDL_HandClassification(handle, frame, cvtdl_object_t *meta)`（手势分类，结果 `meta->info[i].name` + `bbox.score`）
     - 注意：输出是 object 结构（含框+name），**不同于** `cvtdl_class_meta_t`(top5数组)
  3. **官方配套模型**：`hand_det_qat_640x384`、`hand_cls_128x128`、`hand_kpt_cls9`
  4. **`CVI_TDL_GetVpssChnConfig(handle, model, frameW, frameH, idx, chnConfig)`**：取得模型预处理 VPSS 参数
- **结论**：
  - 我错误地设置了 `SkipVpssPreprocess=true`（可能是缺口 A 主因）
  - 正确方向：改回 skip=false，让 TDL 用内部 VPSS 自动预处理
  - `HandClassification` 可能是手势识别的官方正确 API（区别于通用 Image_Classification）

- **下一步行动**（待执行）：
  1. 修改 `test_img_cls_raw.c`：**移除 `SkipVpssPreprocess(true)`**，改回默认 skip=false
  2. 重新编译部署，验证推理是否成功
  3. 若仍需手动：用 `CVI_TDL_GetVpssChnConfig` 配置内部 VPSS 参数
  4. 关注 `HandClassification` 通道（固件 strings 确认存在 `CVI_TDL_HandClassification`）

## 验证 #4：移除 SkipVpssPreprocess(true) → 改回内部 VPSS(skip=false)
- **时间**：2026-08-04
- **目标**：验证"错误设置 skip=true 破坏内部 VPSS"的推测；改回 skip=false 让 `IMAGE_CLASSIFICATION` 推理"已初始化"
- **依据**：PDF 文档 4.2.1.6（839行）——TDL 默认用内部 VPSS 预处理(skip=false)；skip=true 需外部预处理
- **操作**：
  1. 修改 `test_img_cls_raw.c`：`SetSkipVpssPreprocess(..., true)` → `false`
  2. 保留 `CreateHandle2(&tdl,1,0)` + `SetPreParam(factor=0.0078431, mean=1.0, RGB_PLANAR)`
  3. 重新编译 → scp 到评估板 /root/
  4. 运行：`./test_img_cls_raw /root/gesture_sg2000.cvimodel gesture_number1.jpg 128 128 rgb 0.0078431 1.0`
- **预期**：若推测正确，推理不再报 0xc001010b，能输出 top5 分类结果
- **结果**：`SkipVpssPreprocess = false` 后**推理仍报 0xc001010b**（NOT_YET_INITIALIZED）。推测不成立。
- **结论**：内部 VPSS 预处理不是缺口；`IMAGE_CLASSIFICATION` 推理的"未初始化"另有原因。
  - 关键对照：`cvi_sample_classifier` 工具能推理 → 它初始化了**完整媒体框架（CVI_SYS_Init / VB池 / VPSS）**，而我的裸程序只调了 TDL API。
  - **新推测**：TDL 推理前可能必须 `CVI_SYS_Init` + 建 VB 池（VB_PUBLIC 池），否则模型推理通道视为未初始化。
- **下一步**：
  1. 在程序中加入 `CVI_SYS_Init()` + `VB_PUBLIC` 池初始化（参考 tpu-sdk/sample 初始化）
  2. 或改用官方 `CVI_TDL_HandClassification`（输出 `cvtdl_object_t`，官方手势 API）测试
  3. 若仍失败，直接反推 `cvi_sample_classifier` 工具的完整初始化序列复刻

> 已测试：编译+部署+评估板运行完成，结果已回填。

## 验证 #6：改用官方手势 API CVI_TDL_HandClassification
- **时间**：2026-08-04
- **目标**：`IMAGE_CLASSIFICATION` 通道推理一直 010b 失败；改用官方手势专用通道 `CVI_TDL_HandClassification`（输出 `cvtdl_object_t` 含 name/bbox）测试自定义模型
- **依据**：PDF 文档 4.2.6.2 确认 `HandClassification(handle, frame, cvtdl_object_t *meta)` 是官方手势分类 API；固件 strings 确认 `CVI_TDL_HandClassification` 存在
- **操作**：
  1. 新建 `test_img_hand_cls.c`：VB+SYS init → CreateHandle2 → OpenModel(HANDCLASSIFICATION) → ReadImage_Resize → CVI_TDL_HandClassification，输出 meta->info[i].name/bbox.score
  2. 编译 → scp 到评估板 → 运行
- **结果**：
  ```
  VB+SYS init OK
  OpenModel(HANDCLASSIFICATION) OK     ← 模型成功加载
  ReadImage OK 128x128
  === HandClassification Result (size=0) ===   ← 推理正常返回(无010b错误)，仅 size=0
  ```
  - **OpenModel 成功**，推理**未报 0xc001010b**（首次绕过该错误！）
  - `size=0`：推理正常执行但无输出对象
- **结论**：
  1. **`CVI_TDL_HandClassification` 通道成功绕开了"功能未初始化"障碍**——这是有意义的大突破
  2. `size=0` 原因：`HandClassification` 是"检测+分类"语义，期望先检测出手对象再对每个对象分类；而我的模型是**整图分类**（无对象检测），故无对象 → size=0
  3. 说明：官方 `HandClassification` 通道能加载自定义模型并推理，只是语义上需要"对象"概念
- **下一步**：
  1. 确认 `HandClassification` 对"整图分类模型"的输入输出语义——可能需要从 frame 构造一个"整图对象"，或它内部期待检测模型
  2. 关键验证点：`size=0` 是因为"模型没有对象检测能力"还是"我的模型不是它期望的检测模型结构"——可对比官方 `cls_hand_gesture_128_128` 模型跑同程序
  3. 若 HandClassification 与我的整图模型不匹配，仍需解决 `IMAGE_CLASSIFICATION` 的 010b；但现在知道 HandClassification 绕过了它，可作为研究正确预处理的突破口

## 验证 #7：定位官方 HandClassification 正确输入的差异
- **时间**：2026-08-04
- **目标**：官方 `cls_hand_gesture_128_128` 模型用同程序也 size=0，排除模型问题；改研究官方 `sample_img_hand_cls` 的正确用法
- **依据**：官方固件 `sample_img_hand_cls` 之前能跑出 `clsnum:4`，反推其调用链
- **操作**：`strings sample_img_hand_cls` 提取其 TDL API 调用
- **结果**：官方程序调用链为：
  ```
  CVI_TDL_CreateHandle → CVI_TDL_Create_ImageProcessor → CVI_TDL_OpenModel(→HANDCLASS)
  → CVI_TDL_ReadImage(不带Resize) → CVI_TDL_HandClassification → CVI_TDL_FreeObject
  ```
  **关键差异**：官方用 `CVI_TDL_ReadImage`（不 resize，保持原图），我的 `test_img_hand_cls` 用 `CVI_TDL_ReadImage_Resize`（强制 resize 到 128×128）
- **结论**：`HandClassification` 通道可能期望"原图 + 内部根据模型输入自动缩放"，而我强制 resize 到 128×128 或构造的帧结构不匹配，导致 size=0
- **下一步**：
  1. 修改 `test_img_hand_cls.c`：改用 `CVI_TDL_ReadImage`（不 resize）
  2. 由于 `CVI_TDL_ReadImage` 读原图会很大，需确认格式构造；或直接给官方 `sample_img_hand_cls` 传正确的模型+图验证其能输出 clsnum
  3. 若 ReadImage+HandClass 能输出 size>0，则定位成功

## 验证 #9：复刻官方调用链 + 系统性排查 0xC0010109
- **时间**：2026-08-04
- **目标**：复刻固件官方 `sample_img_hand_cls` 的正确调用链（读原图 + 整图 objbox），让 `CVI_TDL_HandClassification` 输出 size>0 的分类结果
- **操作**：改写 `test_img_hand_cls.c` 为：VB池 + `CVI_TDL_ReadImage`(原图)/`ReadImage_Resize`(128) + 整图 objbox(0,0,W-1,H-1) + `CVI_TDL_SetModelThreshold`；逐一打开/部署/运行验证
- **本次突破（解决了库加载问题）**：
  - 运行需 `LD_LIBRARY_PATH=/mnt/system/lib:/mnt/system/usr/lib`（tdl库在 /mnt/system/lib，系统库在 /mnt/system/usr/lib）
  - 编译需显式链接 `-lvpss -lvo`（否则运行时 `CVI_VPSS_*` 符号找不到）
- **结果**：程序成功运行到推理层（VB/SYS、OpenModel、ReadImage、objbox 全部 OK），但 `CVI_TDL_HandClassification` 返回 **`0xC0010109`**：
  ```
  VB+SYS init OK / OpenModel(HANDCLASSIFICATION) OK / SetModelThreshold=0
  ReadImage OK 227x292 (或 128x128) / init objbox: 0,0,226,291
  HandClassification fail 0xc0010109
  ```
- **错误码解码**：`0xC0010109` = 末字节 0x09 = **`CVI_TDL_ERR_VPSS_GET_FRAME`**（对照 cvtdl_errno.h: EN_CVI_TDL_FAILED_VPSS_GET_FRAME=9），源头在 `libcvi_tdl.so` 的 `VpssEngine::getFrame` → `CVI_VPSS_GetChnFrame` 失败
- **已排除的变量**（逐一测试仍 0109）：
  1. VB池尺寸：`MMF_INIT_HELPER2(128,128)` / `(640,480,128,128)` / 精确复刻固件 2×6.2MB blkCnt=1
  2. 句柄：`CVI_TDL_CreateHandle` vs `CVI_TDL_CreateHandle2(&tdl,1,0)`
  3. 读图：`CVI_TDL_ReadImage`(原图227×292) vs `ReadImage_Resize`(128×128)
  4. OpenModel 位置（ReadImage 前/后）、`SetModelThreshold` 有无
- **关键对照**：固件官方 `sample_img_hand_cls`（/mnt/system/usr/bin/ai/）用**同一套固件库** + 完全相同 objbox，`HandClassification ret=0`（仅 cls result 空）。其 NEEDED 链接了**完整媒体框架库**（libvi/vo/vpss/gdc/rgn/isp/sample/venc/vdec/ae/awb/af/cvi_bin/misc/isp_algo），而我的程序只链了 libsys/vi/vo/vpss
- **关键反汇编证据（决定性）**：反汇编固件 `sample_img_hand_cls`（objdump）确认其调用 `CVI_TDL_HandClassification`（地址 0x11070）后**完全不检查返回码 a0**——`0x11074` 直接 `ld a1,48(sp)` 读 `meta.info`，`0x1107a` 只查 `meta.info[0].name[0]` 是否为空，空则打印 "(空)"。**即固件程序即使 HandClassification 返回 0109 也照常打印"(空)"，静默吞掉错误**。这解释了"固件看似 ret=0 跑通，我同一调用却报 0109"的矛盾：固件只是不检查 ret，实际是同一失败。
- **结论**：
  1. **`0xC0010109` 与"完整媒体框架初始化"无关**——已用板上库全链复刻固件 NEEDED 库清单编译（`build_hand_cls_full.sh`，含 atomic_shim.so 导出的 `__sync_fetch_and_add_1`/`__sync_fetch_and_and_1`/`__atomic_compare_exchange_1` 软件实现），运行加载 libvi/vo/vpss/gdc/rgn/isp 全套，但 HandClassification 仍返回 `0xC0010109`（exit 9）
  2. **strace 字节级对比**：固件官方程序与我的程序加载**同一 `/mnt/system/lib/libcvi_tdl.so`**、打开**同一批设备**（/dev/cvi-sys=3,4、/dev/cvi-vi=7、/dev/cvi-vpss=8）、import **完全相同**的 CVI_TDL_* 符号、VPSS ioctl **命令码与返回值逐条一致**（含第9次均返回 `18446744072636235790` 的失败返回）——唯一区别：固件不读 ret、我读 ret 并打印 0109
  3. **真正结论**：用户观察正确——官方演示只有人脸检测（`CVI_TDL_Detection`/FD）真正跑通；`CVI_TDL_HandClassification` 在固件 V2 `libcvi_tdl.so` + 读图/整图 objbox 调用下**本身就返回 0109（VPSS_GET_FRAME 失败），固件样例只是吞掉了该错误**。这不是我的初始化缺陷，而是该 API 路径在此环境下实际不可用
- **下一步（转向可行路径）**：
  1. 放弃 `CVI_TDL_HandClassification` API，改用官方唯一验证可用的人脸检测通路（`CVI_TDL_Detection`+FD）同一实时通道架构
  2. 研究 `CVI_TDL_Isp_Image_Classification`（VT 实时帧通道）或 `/TDL_IMAGE_CLASSIFICATION`/RAW 通道是否在固件库中可用，绕过 HandClassification 的内部 VPSS 裁剪
  3. 以官方 sample_vi_fd/test_img_fd（人脸检测跑通）为基座，在其 VI/VPSS 实时通道上切换手势分类模型

## 验证 #29：gesture_cls 与 TDL 库共享 libcviruntime 全局状态导致冲突（out_num 损坏、进程退出）
- **时间**：2026-08-05
- **目标**：排查集成后 out_num 异常负数 + 进程退出的根因
- **操作**：检查 `libcvi_tdl.so` 的动态依赖与符号引用；集成版运行抓日志
- **结果（根因确认）**：
  1. `libcvi_tdl.so`（TDL 库）NEEDED 本身包含 **`libcviruntime.so`**，且引用 `CVI_NN_Forward`/`CVI_NN_GetInputOutputTensors`/`CVI_NN_RegisterModel` 等 **cviruntime 符号**
  2. 集成版运行时：`[gest] model loaded: ... out_num=-642598800`（**异常负数**），进程最终 DEAD
  3. 独立测试 `cls_cviruntime_test.c`（无 TDL 库）`GetInputOutputTensors` 正常 out_num=1 → **确证是 TDL + cviruntime 共存冲突**
- **结论**：
  1. **根因**：`gesture_cls.c` 直接用 `CVI_NN_*` 注册/推理，与 TDL 库（`libcvi_tdl.so`）内部使用的**同一份 libcviruntime 全局状态**冲突——TDL 已初始化 cviruntime 的 TPU 设备/模型上下文，我的再注册/取 tensor 干扰了它，导致 out_num 读取损坏、进程崩溃
  2. 这是"程序同时用 TDL 和裸 cviruntime"的**状态冲突**，非代码逻辑 bug
- **下一步（解决冲突）**：
  1. 确认手势分类 cviruntime 使用方式与 TDL 解耦（如 TDL 之外的独立 cviruntime 设备/上下文，或确认 cviruntime 是否允许多模型共存）
  2. 或改用手部检测的独立通道（在 TDL 推理前/后用单独 cviruntime 实例），分离状态
  3. 或先验证 cviruntime 多模型共存：在同一进程里 RegisterModel TDL 用的手部模型 + 我分类模型，确认是否都能 GetInputOutputTensors 正常

## 验证 #72：修复 7类手势识别恒输出固定类（TDL FP32 预处理bug → 裸 cviruntime 分类）
- **时间**：2026-08-12
- **现象**：7类模型虽不崩（验证#71）但实时/单图识别**恒输出固定手势**（旧模型恒 number5 0.77，新模型恒 number1 0.9993），换手势不变，无法真正识别
- **决定性定位**：
  1. 裸 cviruntime 在评估板真机直接加载 `gesture_7cls.cvimodel` + 0-255 fp32 RGB 输入 → **正确识别**（t5→number5, t1→number1, tf→fist, tn→thumbs-up）
  2. 而 TDL（tdl_cls7/tdl_gesture_stream）同模型恒输出固定类 → **问题100%在 TDL 预处理路径**
  3. 源码确认：CLS_HAND_GESTURE 走 `RgbImageClassification` → `VpssPreprocessor`（CV181X 默认硬件预处理）。模型输入 tensor 是 FP32(qscale=1.0)，而 TDL 的 VPSS 硬件预处理对 FP32 输出帧**不做正确归一化**（0-255 直通/错误输入）→ 模型收到失真输入 → 恒单类
  4. model_factory mean/std 即使是 [0,0,0]/[1,1,1]（直通配置），TDL的 FP32 路径仍不工作
- **解决方案（双层修复）**：
  1. **模型内置归一化**：`inject_normalize.py` 在 ONNX `input` 后注入 `Sub(128)+Mul(1/127.5)`（即 (x-128)/127.5），使模型自带归一化，TDL 只须直通 0-255。重新校准（26张 test 图 KL 法）并 sym INT8 转换 → `gesture_norm_sym.cvimodel`（md5 2661c0）。model_runner 验证 0-255 输入正确识别
  2. **绕过 TDL 分类，改裸 cviruntime**（最终方案）：改造 `tdl_gesture_stream.c`，手部检测仍用 TDL（正常），手势分类改用裸 cviruntime `cls_norm_infer()`（BGR ROI → 128x128 → 0-255 fp32 RGB NCHW → CVI_NN_Forward → softmax）
- **验证结果**：
  - 实时推流 `:8881`，日志正确显示 `class[0] ... label=4 number4 score=1.00`、`label=2 number2 score=0.31` 等**多变手势识别**
  - 手部检测+分类+画框+软编码JPEG+MJPEG推流全链路稳定（PID 持续存活，imencode 每帧 ~29KB JPEG）
  - 开发机 `curl http://192.168.50.1:8881/` 抓取 7.6-10.6MB MJPEG 流，HTTP 200 `multipart/x-mixed-replace`
- **关键结论**：TDL SDK 对「FP32 输入声明的分类模型」预处理有 bug（VPSS 硬件不归一化）。7类 sym INT8 转出的模型输入恒 FP32，绕开方法：模型内置归一化 + 裸 cviruntime 直接推理（已验证可靠）。**TDL_Classification 对自定义 FP32 输入模型不可用于实际识别**
